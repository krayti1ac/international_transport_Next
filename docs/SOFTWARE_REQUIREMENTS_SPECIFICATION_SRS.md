# وثيقة مواصفات متطلبات البرمجيات والمعمارية الفنية (SRS)

## Software Requirements Specification & Technical Blueprint

**نظام إدارة النقل واللوجستيك الدولي — Trans Bodanon TMS Enterprise**

* **الإصدار المرجعي**: v2.5-Enterprise
* **البيئة التقنية**: Next.js 16 (App Router), Supabase (PostgreSQL 16 with RLS), TypeScript Strict, Decimal.js, Tailwind CSS
* **نطاق التغطية**: الممر الأوروبي البحري والممر الإفريقي البري

---

## 1. نطاق المنظومة والأهداف التشغيلية (System Scope & Objectives)

تعمل منظومة **Trans Bodanon TMS** كمنصة سحابية متعددة المستأجرين (Multi-Tenant SaaS) مخصصة لحوكمة وإدارة أساطيل النقل الدولي للبضائع (TIR) وسلاسل التبريد عبر ممرين استراتيجيين:

1. **الممر الأوروبي البحري (`european_maritime`)**: يبدأ من موانئ المغرب (طنجة المتوسط، الناظور) نحو موانئ جنوب أوروبا (الجزيرة الخضراء، ألميريا، موتريل) وعمق القارة الأوروبية، وتتوقف فيه محركات الديزل أثناء الإبحار مع خضوعه لتشريعات الشباك الوطني للموانئ المغربية (**PortNet**) والتبادل المسبق للبيانات الجمركية الدولية (**IRU TIR-EPD**).

2. **الممر الإفريقي البري (`african_overland`)**: يمتد من أكادير والداخلة عبر معبر الكركارات الحدودي إلى موريتانيا (نواديبو، نواكشوط)، ثم معبر روصو النهري وصولاً إلى السنغال (دكار)، ويتطلب تشغيلاً مستمراً لمحركات الاحتراق الداخلي بنسبة $100\%$ مع خضوعه لتسويات العملات الإقليمية (MRU و XOF) وبطاقات التأمين البنية (CEDEAO/ECOWAS).

### 2.2. التحصين الأمني وقواعد الأمان على مستوى الصفوف (PostgreSQL RLS)

* تُفعل سياسة RLS الإلزامية على جميع الجداول:

```sql
ALTER TABLE trip_orders ENABLE ROW LEVEL SECURITY;

CREATE POLICY tenant_isolation_policy ON trip_orders
FOR ALL USING (
  auth.jwt() ->> 'role' = 'super_admin' OR
  company_id = (auth.jwt() ->> 'company_id')::bigint
);
```

* يُمنع منعاً باتاً استقبال `company_id` من الـ Client Payload في عمليات الإدخال أو التحديث، بل يتم فرضه واستخراجه من الجلسة الموثقة حصراً عبر دالة `getAuthenticatedCompanyId()`.

### 2.3. ضوابط ربط الأجهزة وحوكمة الرخص (Hardware & Device Binding)

* يحظر على حسابات السائقين والعمليات الدخول من أجهزة متعددة غير معتمدة.
* يتم تخزين بصمة الجهاز في جدول `company_devices`، ومطابقة `requestDeviceId` مع `tokenDeviceId` عبر `validateDeviceBinding()`.
* إذا تجاوز عدد الأجهزة المصرح بها سقف `max_devices` المسجل في عقد الشركة، يتم رفض تسجيل الدخول آلياً وتحويل السجل إلى `system_screen_issues`.

## 3. محرك العمليات وحالات الآلة الصريحة (Explicit State Machines)

### 3.1. دورة حياة أمر النقل الدولي (Trip Order State Machine)

تتبع الرحلة مساراً جبرياً محكماً يمنع القفز فوق المراحل أو التراجع غير المصرح به:

```
  ┌──────────┐        ┌──────────┐        ┌──────────┐        ┌─────────────┐
  │  Draft   │ ──(1)─►│ Assigned │ ──(2)─►│ Loading  │ ──(3)─►│ In_Transit  │
  └──────────┘        └──────────┘        └──────────┘        └──────┬──────┘
                                                                     │ (4)
                                                                     ▼
  ┌──────────┐        ┌──────────┐        ┌──────────┐        ┌─────────────┐
  │  Closed  │ ◄─(8)──│  Settled │ ◄─(7)──│Delivered │ ◄─(6)──│Customs_Hold/│
  └──────────┘        └──────────┘        └──────────┘        │   Cleared   │ (5)
                                                              └─────────────┘
```

* **قواعد التحول والانتقال (Transition Guards)**:
* **(1) Draft ➔ Assigned**: يلزم تعيين رأس الشاحنة، والمقطورة، وكابتن مرخص يحمل تأشيرة سارية المفعول تناسب الممر (تأشيرة شنغن للممر الأوروبي أو تأشيرة إفريقية للممر البري).
* **(2) Assigned ➔ Loading**: إصدار أمر النقل الداخلي وتوليد رقم e-CMR الفريد.
* **(3) Loading ➔ In_Transit**: إدخال الوزن الإجمالي الفعلي (Gross Weight)، رقم الختم الجمركي الرصاصي (Scellé)، ودرجة حرارة التبريد المستهدفة.
* **(4) & (5) Customs Gates**: عند اقتراب الشاحنة من سياج طنجة المتوسط أو معبر الكركارات (ضمن نطاق 5 كم)، تتحول الحالة آلياً إلى `customs_hold` حتى إرسال واستلام إشعار العبور الجمركي، لتتحول إلى `customs_cleared`.
* **(6) Customs ➔ Delivered**: يشترط توقيع إثبات التسليم الرقمي e-POD بختم HMAC-SHA256 المشفر.
* **(7) Delivered ➔ Settled**: يشترط تسوية كافة سلف ومصروفات ووقود الكابتن بالكامل في شاشة `/driver-settlements`.
* **(8) Settled ➔ Closed**: أرشفة الملف المالي اللوجستي الموحد (Consolidated Dossier PDF) ومنع التعديل نهائياً.

## 4. التطبيق الميداني والصمود دون اتصال (PWA & Offline-First Core)

### 4.1. بنية التخزين المحلي في IndexedDB (الإصدار 2)

تعتمد المنظومة بنية ثلاثية المستودعات داخل قاعدة بيانات المتصفح `transbodanon_offline_db` لضمان عدم فقدان أي بيانات في المناطق الحدودية والصحراوية:

1. `fuel_receipts_queue`: تخزين بيانات الوصولات وصور الديزل المضغوطة بمفاتيح `id`, `truck_id`, `timestamp`.
2. `pod_signatures_queue`: تخزين تواقيع التسليم الرقمية e-POD مشفوعة بإحداثيات الـ GPS ونسب الثقة.
3. `driver_tasks_queue`: تخزين مراحل استلام وتسليم البضائع مع مفتاح فريد لعدم التكرار (`idempotency_key`).

### 4.2. سياسة فض التعارض والمزامنة (Conflict Resolution Strategy)

* **للبيانات المالية والإيصالات**: تطبيق مبدأ **Append-Only** (عدم الكتابة فوق السجلات القديمة نهائياً بل ترحيلها كسجلات تدقيق تراكمية جديدة).
* **لحالات التتبع وتحديثات الرحلة**: تطبيق مبدأ **Last-Write-Wins (LWW)** استناداً إلى طابع التوقيت الزمني لجهاز العميل (`client_timestamp`) مع التحقق من عدم تعارضه مع توقيت الخادم السحابي.

### 4.3. المسح الذكي لاستهلاك الوقود وضبط التجوال الدولي (Data Roaming Guard)

* عند العمل عبر شبكات الاتصال الدولية أو الاتصال الضعيف (Roaming/2G/3G/SaveData)، يتم ضغط الصور محلياً قبل التخزين بنسبة جودة 0.5 وأبعاد قصوى $800\text{px}$.
* إذا كانت نسبة ثقة محرك الـ OCR أقل من $85\%$، يوسم الإيصال بحالة `manual_review_required` ويُحال تلقائياً لشاشة المحاسب مع منع التكرار الجنائي بناءً على رقم الفاتورة المطبوع واسم المحطة.

## 5. الحوكمة المالية الدقيقة (Strict Financial & Forex Engine)

### 5.1. القاعدة المالية غير القابلة للتفاوض (Decimal.js Absolute Precision)

يُحظر استخدام العمليات الحسابية القياسية لـ JavaScript (`+`, `-`, `*`, `/`) على كافة المبالغ والضرائب والكميات. تُهيأ المكتبة مركزياً:

```typescript
import Decimal from 'decimal.js';
Decimal.config({ precision: 20, rounding: Decimal.ROUND_HALF_UP });
```

### 5.2. محرك التوزيع الذري بالأقدمية (FIFO Payment Allocation Engine)

عند إيداع دفعة بنكية أو نقدية من العميل:

1. يتم جلب كافة فواتير العميل المستحقة وغير المسددة مرتبة تصاعدياً بحسب تاريخ الاستحقاق (`issue_date ASC, id ASC`).
2. تُسدد الفاتورة الأقدم بالكامل قبل الانتقال للفاتورة التالية.
3. في حال السداد الجزئي، تُسجل الفاتورة بحالة `partially_paid` مع تحديث دقيق لمبلغ `paid_amount` والمبلغ المتبقي.
4. في حال السداد الفائض (Overpayment)، يُرحل المبلغ الزائد كإشعار دائن (Credit Balance) لحساب العميل لاستخدامه في الشحنات القادمة دون تركه ككسور عائمة.

### 5.3. فروق الصرف المحققة (Realized Forex Gain/Loss Automation)

عند إصدار فاتورة باليورو (`EUR`) وسدادها بالدرهم المغربي (`MAD`)، يتم احتساب الفارق المالي وتوليد قيد تلقائي في الخزينة:

$$\Delta\text{Forex} = \text{Amount}_{\text{EUR}} \times (R_{\text{Settlement}} - R_{\text{Invoice}})$$

* إذا كان $\Delta\text{Forex} > 0.01\text{ MAD}$: يُسجل كـ **Realized Forex Gain** (إيراد صرف).
* إذا كان $\Delta\text{Forex} < -0.01\text{ MAD}$: يُسجل كـ **Realized Forex Loss** (عبء صرف).

## 6. التحليلات التنبؤية للأسطول (Fleet Predictive AI Analytics)

### 6.1. مؤشر تآكل الإطارات التنبؤي (Tire Wear Index - TWI)

يُحتسب المؤشر لحظياً بناءً على الكيلومترات التراكمية لطرق النقل ومعامل وعورة التضاريس:

$$TWI = \left(\frac{\text{Cumulative Distance (km)}}{\text{Rated Tire Life (km)}}\right) \times \text{Corridor Roughness Factor} \times 100$$

* **معاملات الوعورة المعتمدة**:
* الممر الإفريقي البري: $1.4$ (طرق صحراوية، حرارة عالية، ورمال).
* الممر الداخلي المغربي: $1.1$.
* الممر الأوروبي البحري: $1.0$ (طرق سيارة دولية ممهدة).
* **إجراء التحصين**: إذا بلغ $TWI \ge 90\%$، يتم حظر إسناد الشاحنة للرحلات الدولية وتوجيه أمر استبدال فوري لمدير الأسطول.

### 6.2. مؤشر إجهاد مبردات الشحن (Reefer Stress Degradation Index - SDI)

لقياس سلامة محركات التبريد (Carrier / Thermo King) ومنع تلف شحنات الأسماك والخضروات:

$$SDI = \left(\frac{\text{Engine Hours}}{1{,}500\text{ h}}\right) \times \left(1 + \frac{\sum \vert{}\Delta T > 2^\circ\text{C}\vert{} \times \text{Hours}}{100}\right)$$

* انحراف درجة الحرارة بأكثر من $2^\circ\text{C}$ لمدة تفوق $45\text{ دقيقة}$ يطلق إنذاراً حرجاً عبر **Web Push** لهاتف السائق والعمليات.

### 6.3. مؤشر سرعة سداد العميل وتوقع السيولة (Payment Velocity Index - PVI)

لحساب التدفقات النقدية المستقبلية (Cash Flow Forecast 30/60/90 Days):

$$PVI = \frac{\text{Actual Days to Settle Payment}}{\text{Agreed Invoice Terms (Days)}}$$

* تُضرب تواريخ استحقاق الفواتير القادمة في معامل $PVI$ لتحديد التوقيت الواقعي لدخول السيولة النقدية وسداد تذاكر البواخر والمحروقات.

## 7. الربط الجمركي والموانئ والنزاهة الرقمية (Customs Gateway & e-POD)

### 7.1. معايير التبادل الجمركي المسبق (PortNet & IRU TIR-EPD XML)

* **الممر الأوروبي البحري**:
* توليد ملف الـ XML المطابق لمواصفات شباك موانئ المغرب الموحد (PortNet) متضمناً رقم الـ ICE للعميل، ختم الرصاص، وحجز العبارة البحرية.
* إرسال مباشر عبر `PortNet API` وتثبيت رقم المرجع الجمركي الرسمي (**MRN**) والباركود المينائي.
* إرسال البيان المسبق عبر واجهة **IRU TIR-EPD API** للجمارك الإسبانية والفرنسية قبل وصول الشاحنة للميناء.

* **الممر الإفريقي البري**:
* توليد كشف الترانزيت الجمركي الإفريقي (TRIE) وتثبيت بيانات دفتر المرور الدولي وتأمين البطاقة البنية (ECOWAS).

### 7.2. النزاهة التشفيرية لإثبات التسليم (e-POD HMAC-SHA256)

تُقفل شهادة التسليم فور توقيع المستلم على شاشة الهاتف بحساب الختم الجنائي المشفر:

$$\text{Seal} = \text{HMAC-SHA256}(\text{TripID} \,\Vert{}\, \text{ReceiverName} \,\Vert{}\, \text{Timestamp} \,\Vert{}\, \text{GPS Lat/Lng}, \text{PDF\_SIGNING\_KEY})$$

* أي تعديل في تفاصيل الرحلة أو إحداثيات موقع التسليم يبطل مطابقة الختم تلقائياً أمام خبراء التأمين والجمارك.
